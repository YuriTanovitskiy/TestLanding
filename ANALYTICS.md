# Аналитика Auto CRAFT KZ

## Исключение собственных посещений

- Включить: `https://autocraft.kz/?owner_mode=on`.
- Выключить: `https://autocraft.kz/?owner_mode=off`.

Откройте ссылку включения один раз в каждом используемом браузере каждого устройства. Подтверждение появится на сайте. Отметка хранится в cookie `autocraft_owner` до года; после очистки cookies или в другом браузере её нужно поставить снова. Она действует независимо от Wi-Fi и мобильной сети, только для текущего домена. Это исключение аналитики, а не вход в административную панель.

В режиме владельца GA4 не загружается и события не отправляются. Pages middleware удаляет заранее вставленный Cloudflare beacon из HTML и отдаёт персональный ответ с `private, no-store, no-transform`, предотвращая автоматическое добавление beacon на стороне прокси. Обычные посетители продолжают учитываться. Сетевые HTTP-запросы в Cloudflare Traffic Analytics и записи D1 не исключаются; тестовую заявку этот режим всё равно сохраняет. Прошлые просмотры не удаляются.

После публикации проверяйте отсутствие запросов к `static.cloudflareinsights.com`, `/cdn-cgi/rum`, `cloudflareinsights.com/cdn-cgi/rum`, `googletagmanager.com/gtag/js` и Google Analytics collect при включённом режиме, в том числе после перезагрузки без параметра URL.

Cloudflare Web Analytics остаётся источником статистики посещений. Он не поддерживает собственные события и не сохраняет параметры URL (в том числе UTM): https://developers.cloudflare.com/web-analytics/faq/.

Для источников и действий подключён Google Analytics 4. Идентификатор `G-8RBTY44HDR` из `google.txt` задан в `.env.production` и включается при production-сборке. Обычный запуск `npm run dev` не отправляет данные в этот поток, если идентификатор отдельно не задан в локальном окружении. Сбор на опубликованном сайте начнётся после публикации новой сборки.

## Подключение

1. В Google Analytics создайте ресурс и веб-поток для `https://autocraft.kz`.
2. Получите идентификатор измерения вида `G-XXXXXXXXXX`.
3. Текущий идентификатор уже задан в `.env.production`: он применяется при `npm run build`, в том числе при сборке этого проекта в Cloudflare Pages. Если в Cloudflare задана переменная `VITE_GA_MEASUREMENT_ID`, она имеет приоритет над файлом — проверьте совпадение. Для локальной проверки с отдельным тестовым потоком используйте `.env.local` по образцу `.env.example`.
4. Выполните новую сборку и публикацию. Переменная встраивается Vite во время сборки.
5. В отчёте Realtime проверьте визит и каждое действие. Для проверки на localhost используйте отдельный тестовый поток; исключите собственные посещения при оценке результатов.

## События

| Событие | Значение |
| --- | --- |
| `contact_whatsapp` | Нажатие прямой ссылки WhatsApp |
| `contact_phone` | Нажатие телефонной ссылки |
| `contact_route` | Нажатие ссылки на карты |
| `repair_form_start` | Первое изменение формы за её открытие |
| `repair_form_whatsapp` | Переход из формы в WhatsApp |
| `service_booking_complete` | Успешное сохранение онлайн-записи перед переходом в WhatsApp |

Параметр `placement` показывает расположение действия. При необходимости зарегистрируйте его как специальный параметр с областью действия «Событие» в GA4. Содержимое полей формы не передаётся нашими событиями в аналитику. Форма обсуждения ремонта передаёт текст в WhatsApp. Форма онлайн-записи сначала сохраняет запись в Cloudflare D1, затем открывает WhatsApp, где клиент сам подтверждает отправку сообщения. Нажатия не равны сообщениям, звонкам и ремонтам.

## Конверсия онлайн-записи

Событие `service_booking_complete`, параметр `placement=service-booking`,
отправляется только после успешного ответа API с идентификатором записи.
Ошибки проверки полей, HTTP 409, недоступность сервера и простое нажатие на
кнопку без сохранения заявки не считаются конверсией. В событие не входят
имя, телефон, автомобиль, VIN, описание, дата/время или идентификатор записи.
Перед уходом в WhatsApp ждём callback Google tag либо не более 1,5 секунды;
при блокировке аналитики переход всё равно выполняется.

Повторная ссылка «Отправить запись в WhatsApp» на экране подтверждения не
отправляет ещё одну `service_booking_complete` или `contact_whatsapp`.
Повторная отправка сообщения сама по себе не создаёт новую запись.

Завершить в интерфейсе Google (создания конверсий в доступных действиях Windsor нет):

1. В GA4 ресурса с потоком `G-8RBTY44HDR` отметить
   `service_booking_complete` как ключевое событие.
2. В Google Ads аккаунта `152-803-2066` создать конверсию из этого события
   связанного ресурса GA4, название «Сайт — онлайн-запись на сервис».
3. Категория: запись на приём; роль: основная; подсчёт: одна;
   без выдуманной денежной ценности. Проверить включение цели в текущую кампанию.
4. Не создавать параллельно вторую конверсию на обычное нажатие той же кнопки
   или на просмотр секции: это приведёт к учёту незавершённых заявок/дублей.

Это подтверждение сохранённой записи, а не факта отправки WhatsApp-сообщения
или выполненного ремонта. Настройка события в коде не означает, что оно уже
импортировано в Google Ads. Исторические записи не отправляются задним числом.

Проверка логики: `node --test server/analytics.test.mjs`.

GA4 по умолчанию отправляет просмотр страницы, включая URL и источник. Для формы отключите автоматическое измерение взаимодействий с формами, чтобы использовать только описанные события. Не добавляйте личные данные клиентов в UTM или URL. Не устанавливайте второй Google tag для того же потока параллельно этой интеграции.

Пример ссылки для Instagram: `https://autocraft.kz/?utm_source=instagram&utm_medium=social&utm_campaign=profile`. Для карт используйте отдельные значения `utm_source`, например `2gis` и `google_maps`. Источники смотрите в отчёте привлечения трафика. Неизвестный источник и география сами по себе не доказывают наличие бота; сравнивайте Cloudflare, события и реальные обращения. Абсолютного определения людей и роботов эта интеграция не даёт.
